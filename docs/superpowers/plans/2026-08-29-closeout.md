## Deep analysis — where we actually are

**Everything contracted is live and merged.** Tickets 1–3 shipped; `main` (`9ae0466`) equals production tree-for-tree; 119 tests; both crons run unattended; every change has a rollback artifact.

**The one approved-but-not-done item is the flag.** Its risk profile is now low: identity is content-derived, dates are anchored and format-safe, the exact pass clusters per event and is idempotent (`suppressed 0` on re-run), and the replay converged. What remains unknown is only what a full real night looks like — hence one observed night, judged against a captured legacy baseline (titled 22–28 %, dated 21–27 %), with a one-line revert.

**Why the review queue creeps (+18/night) and why the flip ends it.** The legacy path writes one row per slide; nameless slide rows that carry an artist or venue are "ambiguous" by the rules and are queued rather than hidden. The structured path writes one row per event, so that class of pair stops being created. Expect the queue to flatten from the first structured night; the 135 existing pairs are the owner's to review (they are genuinely ambiguous by design).

**What is NOT a problem.** Disk (80 %) grows ~120 MB/day organically → ~50 days of headroom; the jump was my own deploy copies (now rotated). The 33k legacy unkeyed posts never get re-matched, by design; the nightly pass reconciles overlap. The 5 keeper mis-picks from the first collapse are harmless and unchanged.

**What is gated on the owner, not on code.** Repo privacy (→ docs commit), credential rotation (coupled to ingestion), JWT key, Elastic IP, the cross-post auto-merge (earmarked), and — after night 1 — whether the flag stays on.

**Two known debts worth naming, neither urgent.** (1) `same_post_is_redundant` compares tokens, so an Instagram handle used as a title ("justlikeheavenfest") never matches its spelled-out twin; a squashed comparison would fix it but changes what the nightly collapses → test-first, separate change. (2) `is_duplicate` and `suppressed` are dual-written; unify when that code is next touched.
